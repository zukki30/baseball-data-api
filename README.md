# baseball-data-api

NPBの終了済み試合や過去の成績を、スコアブック・Webページを確認しながら手入力する野球記録アプリの設計資料です。先攻・後攻の両チームを対象に、個人・チーム・リーグのデータを絞り込み、比較して考察することを目指します。試合、打席、投球をたどり、球場・投手の投球腕・球種・コース・スイングの有無でも振り返れます。

## 設計ドキュメント

| 読みたい内容 | ドキュメント |
| --- | --- |
| 終了済み試合の打席・走塁・交代、過去成績の入力、成績の絞り込み・比較 | [試合を記録する](docs/scorekeeping.md) |
| 1球ごとの入力、投手別の持ち球の選択・追加、ゾーンぎりぎりの球 | [投球を記録する](docs/pitch-tracking.md) |
| プレーと選手成績の関係、記録が一部しかない試合、年度集計の二重計上防止 | [データモデルと集計](docs/data-model.md) |
| 画面ごとのエンドポイント、投球の登録・検索例、訂正・再送の扱い | [API設計案](docs/api.md) |

## 確定した利用方針

2026年11月24日の回答を反映しています。

| 項目 | 方針 |
| --- | --- |
| 対象 | 初期はNPB。将来のMLB等への対応も想定する |
| 利用者 | 本人が入力・編集・閲覧し、他の人には閲覧を許可できる |
| 目的 | 個人・チーム・リーグごとの記録を収集し、絞り込み・比較して考察する |
| 入力元 | 本人が確認したスコアブックやWebページ |
| 入力時期 | 試合終了後、または過去の記録を確認できた時点 |
| 入力方法 | 手入力。資料に応じて打席・投球の詳細、試合成績、年度合計を登録する |
| 持ち球 | その投手が使用したことを確認できる球種を候補にし、追加の確認に応じて候補を増やす |

## 記録の範囲と現在地

- **試合の詳細入力**では資料に沿って両チームの打順と投手を引き継ぎ、打席結果、走者の移動、選手交代を記録する。1球ごとの球種・コース・打者の反応も入力できる。
- **過去の記録**は試合単位と年度合計の両方を扱う。最終スコアだけの試合、決め球だけ判明した打席も登録対象にする。集計には対象範囲ごとに採用元を一つ選ぶ。
- **投球入力**では投手の持ち球から選び、新しく確認した球種をその場で追加する。コースは捕手視点で記録でき、ゾーン境界の内外が判別できない場合も保存する。

画面操作は会話内のデモで試作した段階です。このリポジトリに収録しているのは設計資料で、APIサーバーとDB永続化は未実装です。PostgreSQLの論理構成、URL・フィールド名、比較画面の具体的な指標やフィルターは実装に向けた案です。

NPBで最初に扱う年度・一軍やファーム等の範囲・試合区分、他の人への閲覧許可の方法、境界付近とする帯の幅は今後確定します。適用する競技ルールは対象年度と大会に対応させます。
