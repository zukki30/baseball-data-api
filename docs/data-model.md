# データモデルと集計

初期はNPBの終了済み試合・過去資料を本人が手入力する。両チームの試合を通して、打順・投手・走者・得点の変化を記録する。判明した1試合の成績と選手の年度合計も登録できる。個人・チーム・リーグで絞り込み、比較する。以下はこれらの要件を満たす論理設計案。テーブル名と列名は説明用で、DDLや実装の完了を示すものではない。

## 試合と出場選手

| テーブル案 | 1行が表すもの | 主な情報 |
|---|---|---|
| `players` / `teams` | 選手／チーム | 選手IDは打撃・投球で共通。チームには独立したIDを付ける |
| `leagues` | リーグ | リーグIDと名称、NPB・MLB等を示す組織識別子。NPB内のリーグを個別に識別する |
| `team_league_memberships` | チームの所属リーグと有効期間 | チームID、リーグID、有効な期間。試合日や年度資料の所属範囲に適用する |
| `seasons` / `competitions` / `venues` | シーズン／大会／球場 | 年度、大会・試合区分、球場名等 |
| `games` | 1試合 | 開催日、球場、先攻・後攻、両チームそれぞれの当時の所属リーグ、シーズン、大会、試合区分、試合状態、記録状態。同日同カードの第1・第2試合も別IDで識別 |
| `game_rosters` | 試合当日のチームと選手の組 | 試合時の所属、背番号、出場の事実。登録選手と実際の出場を区別 |
| `starting_lineups` | 各チームの先発起用 | 出場選手、打順枠、先発守備位置、先発投手。DH制では打順を持たない先発投手も記録 |

試合開始時の打順・守備を保存し、後の交代は発生順に追加する。当時の所属や打順は、移籍や選手交代の後も照会できる。資料の少ない過去試合は、対戦カードや最終スコアなど、判明した範囲から登録する。

リーグの識別と、試合・年度成績の大会や試合区分をそれぞれ保持する。リーグをまたぐ対戦では、打撃記録は打撃側、投球記録は守備側のチーム・リーグに帰属させる。検索には対象側と対戦相手側の所属を使う。所属が不明な過去資料は不明のまま保持し、現在の所属から過去のリーグを補完しない。

### 試合状態と記録状態

終了済み試合を転記するため、実際の試合状態 `game_status` と、転記・照合の進み具合 `recording_status` を別に持つ。初期の入力対象は終了済みの試合。記録状態は `DRAFT` と `CONFIRMED` を持ち、資料との照合で確認済みにする案とする。本人による訂正時は記録を再確認できる状態に戻す。投球の網羅性、個人成績の不明項目、記録状態はそれぞれ保存する。直接入力する年度成績にも記録状態を持たせ、比較時の条件に使えるようにする。

### 所有者・閲覧権限・出典

初期は本人が全登録・更新を行い、他の人には閲覧を許可できる。認証済みの本人を編集者として識別し、試合や年度成績に所有者を保持する案とする。選手・チーム・リーグ・球種・持ち球の編集も本人が行う。閲覧の認証方式や共有方法は今後確定する。

`record_sources` に資料の種類、名称、任意のURL、ページや記事内の位置、確認日などを保持し、試合・転記成績・個別の記録から参照する案とする。同じ出典は試合から打席・投球へ引き継げる。持ち球の使用確認には、投手と球種の組、出典、確認できた対象年・試合を関連付ける。資料をアプリへ登録した日と、資料に記載された試合日・年度をそれぞれ保持する。

## 打席・プレー・投球

| テーブル案 | 1行が表すもの | 主な情報 |
|---|---|---|
| `game_plays` | 試合内で順序を持つ記録 | 試合ID、順序、回・表裏、種類、関連する打席ID。打席結果、走塁、交代等を同じ時系列に置く |
| `plate_appearances` | 打席の開始から終了まで | 開始時に発行するID、打順枠、開始時の打者・投手、状態、成立時の `closing_play_id`、投球記録の網羅性 `pitch_coverage` |
| `pitches` | 実際に投げた1球 | 打席ID、打席内の投球順、試合内の該当プレー、実際の投手・打者、球種、投球位置、投球結果 |
| `runner_advances` | あるプレーでの打者走者・走者1人の移動 | プレーID、選手、出発地点、到達塁／本塁／アウト、移動理由。得点が認められたかも記録 |
| `lineup_changes` | 交代・配置変更 | プレーID、チーム、対象の選手・打順枠・役割と変更後の値。同時交代は同じプレーにまとめる |
| `pitch_types` / `pitcher_repertoire` | 球種／投手の持ち球 | 球種の共通識別子、投手ごとの候補。投球判定や位置の定義は[投球記録](./pitch-tracking.md)を参照 |

打席の途中で投球や走塁を先に登録できるよう、打席IDは開始時に発行する。打席が成立したプレーに限り、その打席の `closing_play_id` を設定する。打席結果と公式記録上の帰属先は確定時に持たせる。打席途中で投手・打者が代わった場合は、各球を実際の対戦に残したうえで、確定した成績の帰属も表現できる。

試合内の順序は試合ごとに一意とし、打席内の投球順とは別に管理する。投球中に盗塁した例では、1つのプレーに投球と進塁を関連付ける。二死から盗塁死で攻守交代した例では、走者のアウトを記録して打席を未成立で終了し、次の攻撃は同じ打順枠から再開する。

**1操作の保存単位は1つのプレー。** 最終球で適時打になった場合、該当する投球、打席の確定、各走者の移動、認められた得点を同じトランザクションで反映する。すでに保存した最終球を確定時に再登録しない。配球が不明な過去の安打も、打席結果だけで登録できる。`pitch_coverage` で「全投球を記録」「一部のみ」「投球記録なし」を区別する。

保存した順序と原記録からスコア、アウト、塁上の選手、両軍それぞれの次打順を導出する。訂正では以降のプレーを再評価し、走者や打順が成立しなくなった位置を記録員に示す。APIの保存・訂正操作は[API設計](./api.md)を参照。

## 過去資料と集計の採用元

転記した数字には出典と対象範囲を残す。プレーから導出した試合成績、転記した試合成績、転記した年度成績をそれぞれ保持し、**集計対象ごとに採用する値を一つ選ぶ**。

| 粒度 | 採用元を選ぶ単位 | 成績に使う記録 |
|---|---|---|
| 試合 | 試合 × 選手 × 打撃／投球 | 詳細プレーからの集計、または転記した試合の成績行。チームの最終得点は別管理 |
| 年度 | 選手 × シーズン × 大会・試合区分 × 所属範囲 × 打撃／投球 | 採用した試合成績の合算、または同じ範囲の年度成績行 |

試合の直接入力は `game_team_scores`、`game_batting_lines`、`game_pitching_lines` に保持する案とする。年度の直接入力には `season_batting_summaries` と `season_pitching_summaries` を使う。試合の打撃・投球成績表には採用元（`DETAIL`／`SUMMARY`）と記録範囲を持たせ、年度ごとにも採用元（`GAME_RECORDS`／`SEASON_SUMMARY`）を明示する。自責点、勝敗、セーブなど記録員が確定する項目は、詳細入力の試合でも補完できる。年度の所属別成績と全所属合計は範囲が重なるため、同じ通算値に足す対象を所属別か全所属合計のどちらかに揃える。

例えば資料に年度120安打とあり、後から判明した数試合に20安打分の内訳がある場合、年度合計を採用した表示は120安打。20安打分のプレーは対戦相手別の分析に使い、「記録のある試合分」と表示する。詳細の追加だけで採用元は切り替えない。

所属範囲にはチームと当時のリーグを含める。複数の所属にまたがる年度合計は、元資料の範囲を保持する。チーム別・リーグ別の内訳を計算する際は、その範囲が判明している行を採用する。

## 個人・チーム・リーグの集計と比較

比較画面の初期案として、既存の試合成績・個人成績を対象ごとに集計する。チームやリーグの年度合計を直接転記する専用画面は、扱う資料を確認した上で追加する候補とする。

- 打撃は打者側、投球は投手側の所属でグループ化する。相手チーム・相手リーグは別の絞り込み条件として扱う。
- 年度途中の移籍は各記録の所属に基づき集計する。同じ範囲の所属別成績と全所属合計には、既存の採用元の方針を適用する。
- 打率等は集計した基礎数値から計算する。指標ごとに必要な数値が判明した共通の対象範囲を使い、分子・分母・不明件数を返す。
- 集計対象の開催試合数は、記録した試合IDの重複を除いて数える。選手の出場試合数は別指標とし、年度成績表の記載値も採用元の規則に従って保持する。チームごとの出場数を合算する値も別の指標名にする。年度合計だけの資料で開催試合の重複を除いた件数を確認できない場合、その件数は不明として返す。
- 年度合計から選手成績を示せる場合も、コースや球種の分析には条件を適用できる投球を使う。日付・対戦相手等の条件には、その内訳が判明した資料を使う。
- 対象の全試合・全選手が揃ったと確認できるまでは、チーム・リーグの値に「入力済みデータの集計」と対象件数を添える。全体の対象件数が不明な場合は不明を返す。

比較結果には対象、適用条件、集計値、率の分子・分母、採用元、記録範囲、不明件数を添える案とする。確認済みの記録を初期表示に使う案とし、下書きを参照する際は記録状態を明示する。対象ごとに資料の揃い方が異なる場合も、同じ表示形式で範囲を確認できるようにする。

## 数値と表示

- 不明は `null`、確認済みのゼロは `0`。一部の試合で盗塁が不明なら、判明分の合計と対象試合数を表示する。試合終了と記録の網羅性も別々に管理する。
- 投球回は投手が記録したアウト数の整数で保存する。5回2/3は17アウト。打率は合計安打÷合計打数、防御率は9回換算なら合計自責点×27÷合計アウト数で算出する。
- 率を算出する基礎値が欠けるときや分母が0のときは、数値を未算出とする。過去資料に率だけが残る場合は出典付きの記載値として保持し、件数を推定して通算しない。
